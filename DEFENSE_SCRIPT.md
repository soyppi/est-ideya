# Речь для защиты «Есть идея»

Рабочий вариант на 6–8 минут плюс вопросы. Отдельный регламент организатора не предоставлен. Ведущий разработчик и основной докладчик — Мария Кориненко. Распределение выступлений ниже предложено для репетиции; команда согласует его с фактическим вкладом.

## 1. Мария Кориненко: продукт и архитектура, 60 секунд

«Наш проект называется “Есть идея”. Здесь студенты предлагают улучшения для колледжа: описывают проблему, предлагают решение, выбирают категорию. Другие участники поддерживают и обсуждают предложение. Модератор сообщает решение, а история сохраняет каждое объяснение.

Я выступаю ведущим разработчиком и отвечаю за интеграцию клиента с Supabase и выпуск приложения. Клиент написан на HTML, CSS и JavaScript. Supabase Auth управляет входом, а PostgreSQL хранит идеи, голоса, комментарии и решения. Сервер проверяет права независимо от того, какие кнопки видны на странице».

Показать титул, сайт и SCHEMA.md. Не обещать автономную работу облачной базы без интернета.

## Ответы на вероятные вопросы

**Почему нельзя добавить два голоса?** Составной первичный ключ votes(user_id, idea_id) и идемпотентный set_idea_vote. Ограничение проверяется PostgreSQL.

**Можно ли повысить роль запросом из браузера?** Права UPDATE на role не выданы. RLS и защищённый admin_set_moderator проверяют текущего администратора. Регистрация создаёт user.

**Что будет при сбое между статусом и историей?** Оба изменения находятся в одной транзакции RPC. При ошибке откатываются вместе, уведомление также не создаётся отдельно.

**Почему публичный ключ лежит в config.js?** Publishable/anon key предназначен клиенту. Доступ ограничивают JWT пользователя, RLS и права SQL. Service-role и SMTP-секрет клиенту не передаются.

**Где сохраняются данные?** В PostgreSQL Supabase. В памяти страницы хранится только несохранённый черновик чата. В sessionStorage есть вспомогательный признак восстановления пароля.

**Почему тесты используют PGlite?** Он исполняет реальную схему и ограничения в отдельной временной базе без порчи демонстрации. Auth-контекст воспроизводится, а доставку писем, разные HTTPS-соединения и весь браузерный сценарий проверяют отдельно.

**Какие ограничения остались?** Не выполненная до аккаунтов приёмка, зависимость от сети/SMTP, стандартный лимит ленты Supabase и отсутствие проверки большого объёма. Точный список — TEST_REPORT.md.
