## Запуск готового проекта

Нужны Node.js 22+ с npm, браузер и интернет для Supabase. Проверено с Node.js 24.14.0. Сборки клиента нет.

```sh
git clone https://github.com/soyppi/est-ideya.git
cd est-ideya
npm ci
npm start
```

Откройте http://127.0.0.1:8780/ . Сервер слушает только этот компьютер. В поставленном config.js указан рабочий Supabase и публичный publishable key. Перезапуск сервера не удаляет облачные записи. Без интернета база и авторизация недоступны.

```sh
npm test
```

Тесты используют отдельную временную базу, рабочие записи не меняются. Результаты и границы — [TEST_REPORT.md](TEST_REPORT.md).

## Роли и ограничения

Гость читает открытые идеи, чат и историю. Участник публикует, редактирует своё новое, голосует за свои и чужие идеи и пишет сообщения. Модератор дополнительно рассматривает и скрывает записи. Администратор назначает модераторов через «Участники» и видит журнал. Регистрация всегда создаёт user; самоповышение запрещено. Для назначения модератора email должен быть подтверждён. Своя роль администратора и другие администраторы защищены.

```text
Новое → На рассмотрении
На рассмотрении → Принято / Отклонено
Принято → Реализовано / Отклонено
```

Последние два статуса конечные. Поддержка и обсуждение разрешены во всех открытых статусах. Голоса не меняют статус. RLS скрывает удалённую идею и её связи от гостя и обычного участника, включая прямой API-запрос.

Имя: 1–80, заголовок: 3–120, проблема/решение: 1–4000, сообщение/причина: 1–2000 символов. Нужен видимый текст, пробелы по краям обрезаются. Пароли не обрезаются и не нормализуются. Категории: Учёба, Инфраструктура, Досуг, Питание, Другое. Ограничения действуют в PostgreSQL.

## Установка своего Supabase

1. Создайте проект и выполните весь supabase_schema.sql в SQL Editor. Он включает текущие миграции и допускает повторное применение. Локальный PostgreSQL не нужен.
2. Скопируйте config.example.js в config.js. Укажите Project URL и publishable/anon key. service_role, пароль базы и SMTP-секрет в клиент не добавлять.
3. В Authentication → URL Configuration задайте Site URL с завершающим `/`. Для публикации: `https://soyppi.github.io/est-ideya/`. В Redirect URLs добавьте её и `http://127.0.0.1:8780/` для локальной проверки.
4. Включите Email-провайдер. Если подтверждение email включено, настройте SMTP. Почтовый домен должен существовать и принимать письма. Встроенная отправка Supabase имеет ограничения получателей и квоты. В текущем проекте отдельный SMTP уже настроен, пробная доставка подтверждена владельцем.
5. Зарегистрируйте и подтвердите владельца. Владелец базы после проверки UUID один раз выполняет `update public.profiles set role='admin' where id='ПРОВЕРЕННЫЙ_UUID';`. Дальше назначения идут через интерфейс.
6. GitHub Pages: main, `/ (root)`, без сборки.

Для старой базы вместо полного файла применяются по порядку: admin_migration.sql, requirements_migration.sql, visible_text_migration.sql, interactions_migration.sql, profiles_migration.sql. Они уже применены к опубликованному проекту. Связи и серверные функции — [SCHEMA.md](SCHEMA.md).

## Учебные аккаунты и демоданные

**На 5 ноября четырёх учебных аккаунтов нет. Это незавершённый обязательный пункт М01/М02 и раздела 5 трека.** По решению владельца она создаёт их через регистрацию с доступными для подтверждения email.

| Аккаунт | Роль | Назначение |
|---|---|---|
| Демо: автор | user | Публикация и редактирование своего нового |
| Демо: голосующий | user | Поддержка и сообщения |
| Демо: модератор | moderator | Рассмотрение и скрытие |
| Демо: участник | user | Проверка чужих записей |

Назначьте moderator только третьему. Данные входа передайте жюри отдельно по JURY_ACCOUNTS.template.md. Не используйте личные аккаунты студентов и не публикуйте пароли.

В приватной копии demo_reset.sql замените четыре адреса `.invalid` на реальные подтверждённые учебные email. `.invalid` — пример, почту не принимает. Скрипт проверяет четыре разных аккаунта и их роли. Выполните весь файл в SQL Editor.

Восстанавливаются семь идей с ID от -91007 до -91001: шесть открытых, все пять статусов и категорий, разные счётчики, идея без поддержки, несколько переходов, скрытая идея и комментарий. Повтор заменяет только зарезервированный демонабор и его связи; возвращает автора, дату и тексты. Обычные идеи и аккаунты не удаляет. Аккаунты не создаёт. Не используйте эти ID для своих записей.

## Автоматические тесты

npm test запускает test-db.cjs и test-client.cjs. PGlite выполняет настоящую схему PostgreSQL с имитацией только auth.users/auth.uid; неиспользуемый pgcrypto исключён. Проверяются серверные права, чужие записи, роли, голоса, переходы, история, скрытые прямые запросы, невидимый текст, ответы, уведомления, аватарки и повторная установка. Клиентские тесты вызывают настоящие обработчики форм с тестовым SDK.

Конкурентные HTTPS-запросы — test-live.cjs в **отдельном тестовом Supabase** с той же схемой:

```sh
cp test.env.example .env.test
# Заполните .env.test локально и установите TEST_ALLOW_WRITE=yes
node --env-file=.env.test test-live.cjs
```

В PowerShell можно использовать Copy-Item вместо cp. Переменные: TEST_SUPABASE_URL, TEST_SUPABASE_KEY (публичный), TEST_ALLOW_WRITE и TEST_{AUTHOR,VOTER,MOD}_{EMAIL,PASSWORD}. Тест получает независимые токены, отправляет восемь одновременных голосов и четыре изменения статуса, проверяет один голос/событие истории и сохранность чужого голоса. Создаёт одну тестовую идею и скрывает её в finally. .env.test исключён из Git. **Пока не запущен: учебных аккаунтов нет.**

Три сценария живой приёмки — [DELIVERY.md](DELIVERY.md). Полный повторный вход в независимых сессиях, Chrome/Edge с фиксацией версий ещё нужно проверить. Встроенный Chromium не заменяет оба браузера.

Уведомления: последние 50, счётчик раз в 20 секунд. Поиск участников: по 20. Лента использует стандартный лимит Supabase; для большого потока нужны серверная пагинация и агрегация.
