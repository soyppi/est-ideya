# Есть идея

Студенческие инициативы: проблема и решение, поддержка, обсуждение, рассмотрение с объяснением и историей.

Сайт: https://soyppi.github.io/est-ideya/ . Репозиторий: https://github.com/soyppi/est-ideya . Версия интерфейса 20261029-2. Сдаваемый SHA — последний коммит main после публикации.

## Обсуждение как чат

Кнопка «Обсудить» в ленте открывает отдельное окно чата. Название карточки открывает подробности идеи; из чата к ним ведёт кнопка «Об идее». Сообщения используют прежнюю таблицу comments и защищённую функцию submit_comment, поэтому существующие обсуждения сохраняются. Автообновление выполняется каждые 5 секунд, пока окно открыто и вкладка видима. Последние 200 сообщений загружаются сразу, более ранние доступны по кнопке. Черновик сохраняется в памяти текущей страницы между открытиями, при выходе из аккаунта очищается. Обновление страницы удаляет несохранённый черновик. На компьютере Enter отправляет сообщение, Shift+Enter добавляет строку; на сенсорном устройстве для отправки предусмотрена кнопка. Гости читают, авторизованные участники пишут, модераторы могут скрывать сообщения с причиной. Новая миграция базы не нужна. Логика статусов в этом обновлении не менялась.

## Архитектура и установка

HTML/CSS/JavaScript без сборки, GitHub Pages, Supabase Auth и PostgreSQL. SDK 2.118.0 включён в supabase.vendor.js (лицензия SUPABASE-LICENSE). Действия сохраняются в облачной базе. RLS ограничивает доступ, серверные функции выполняют рассмотрение и мягкое удаление; статус и история меняются атомарно. Тестовых заглушек в сайте нет.

1. Создайте проект Supabase, выполните весь supabase_schema.sql в SQL Editor. Схема применяется повторно транзакционно. Для обновления старой версии выполните admin_migration.sql и requirements_migration.sql. Последняя миграция уже применена к опубликованной базе.
2. Скопируйте config.example.js в config.js, задайте Project URL и публичный publishable/anon key. Секретный service_role в клиент не добавлять.
3. В Authentication → URL Configuration укажите адрес сайта с завершающим /. Для локального запуска добавьте http://127.0.0.1:8780/ в Redirect URLs.
4. Зарегистрируйте и подтвердите владельца. Первого администратора владелец базы назначает по проверенному ID: `update public.profiles set role='admin' where id='UUID_ВЛАДЕЛЬЦА';`. Не используйте неизвестный ID.
5. Нужен Node.js 20+. Выполните `npm ci`, затем `npm start`; откройте http://127.0.0.1:8780/ . Сервер слушает только этот компьютер. Нужен доступ к настроенному Supabase. Отдельный PostgreSQL и Python не нужны.
6. Публикация: GitHub Pages → main → /(root). Сборка не нужна.

## Роли и ограничения

Гость читает открытые идеи, обсуждения и историю. Участник создаёт и редактирует свои новые идеи, поддерживает (включая свои), снимает свой голос и комментирует. Модератор меняет статусы с объяснением, скрывает записи с причиной, видит скрытое и восстанавливает идеи. Администратор назначает и снимает модераторов через «Участники». Своя роль и роль администратора защищены; целевой email должен быть подтверждён, назначения записываются в закрытый журнал. Регистрация создаёт только user.

Переходы: Новое → На рассмотрении → Принято → Реализовано; из На рассмотрении и Принято можно Отклонено. Последние два статуса завершают рассмотрение. Голосование и обсуждение доступны во всех открытых статусах.

Имя 1–80, заголовок 3–120, проблема/решение 1–4000, комментарий/причина 1–2000 символов после обрезки пробелов. Категория только из пяти значений. Ограничения действуют в PostgreSQL. Формы блокируют повторное нажатие; UUID запроса защищает публикации и комментарии от повторного создания после сетевого сбоя. Голос задаётся явно, уникальный ключ и блокировка защищают от гонок. Ошибка сохраняет текст формы. Устаревшее редактирование проверяет возвращённую запись, а не только отсутствие ошибки.

## Четыре учебных аккаунта и демоданные

По решению владельца аккаунты будут созданы ею через обычную регистрацию. Используйте четыре доступных для подтверждения email, имена «Демо: автор», «Демо: голосующий», «Демо: модератор», «Демо: участник». Через аккаунт администратора назначьте модератора только третьему, остальные остаются user. Пароли передайте жюри отдельно, не публикуйте в репозитории. Домен .invalid в примере SQL не принимает почту и для регистрации не подходит.

В приватной копии demo_reset.sql замените четыре example-email на фактические подтверждённые аккаунты и выполните в SQL Editor. Скрипт проверяет наличие аккаунтов и роль модератора. Набор: семь идей, шесть открытых, все пять статусов/категорий, разное количество голосов и комментариев, идея без поддержки, несколько решений в истории, скрытые идея и комментарий.

Повторный запуск восстанавливает только идеи с ID от -91007 до -91001 и их связи; заменяет учебные комментарии, голоса и историю. Обычные записи и личный аккаунт владельца не затрагивает. Аккаунты скрипт не создаёт. Состояние подготовки указано в TEST_REPORT.md.

## Автоматические тесты

```sh
npm ci
npm test
```

PGlite запускает настоящую SQL-схему в отдельной временной базе. Проверки: миграции дважды, ограничения, роли и самоповышение, чужие изменения, голоса и снятие своего, переходы/причины/история, скрытые прямые запросы, повторное восстановление демонабора. auth.users/auth.uid воспроизведены, неиспользуемый pgcrypto исключён. Рабочая база не изменяется. Тест клиента проверяет конфигурацию, поиск, устаревшие ответы и авторизацию. Доставку писем этот набор не проверяет.

Настоящие конкурирующие HTTPS-запросы: `npm run test:live` в отдельно обозначенном тестовом Supabase с той же схемой. Переменные окружения: TEST_SUPABASE_URL, TEST_SUPABASE_KEY (публичный ключ), TEST_ALLOW_WRITE=yes и TEST_{AUTHOR,VOTER,MOD}_{EMAIL,PASSWORD}. Пароли не коммитить. Тест использует независимые токены, отправляет 8 одновременных голосов и 4 изменения статуса, проверяет одну запись истории, сохранность чужого голоса, запреты и скрытые прямые запросы. Создаёт одну учебную идею и скрывает её в finally. Результаты и границы проверки в TEST_REPORT.md.

## Обновление 29 октября: формы, почта и дизайн

Светлая синяя тема с жёлтой звездой, адаптивные карточки и мобильная навигация. Лента, пять категорий, фильтры, личный кабинет, управление ролями, модерация, история и отдельный чат сохранены. SVG-иллюстрации находятся в репозитории; внешние шрифты и изображения не требуются.

На существующей базе выполните `visible_text_migration.sql` после прежних миграций. Новый `supabase_schema.sql` уже включает её. Проверка запрещает текст, состоящий только из пробелов, невидимых управляющих символов, комбинируемых знаков или пустых заполнителей: имена, заголовки, проблема/решение, сообщения, объяснения и причины скрытия. Она работает в формах, прямых записях таблиц и RPC. Обычные буквы, акценты и emoji разрешены. Старые записи не переписываются; ограничения NOT VALID применяются к новым и обновляемым строкам.

Регистрация допускает собственные и международные домены (домен переводится в IDNA), без списка разрешённых почтовых провайдеров. У домена должна существовать рабочая почта. Ошибка `email_address_invalid` от Auth означает отказ сервиса, а не запрет всех собственных доменов. 29 октября в проекте подключён отдельный SMTP Яндекс.Почты; доступ почтовым программам включён. Пробное письмо входа на почту владельца получено (подтверждено владельцем). Для подтверждений на произвольные адреса нужно настроить свой SMTP в Supabase → Authentication → Emails → SMTP Settings. Встроенный сервис имеет общий лимит и ограничения получателей. Подтверждение email оставлено включённым. Локальная пауза повторной отправки улучшает UX, но не заменяет серверную защиту от злоупотреблений. Исчерпание квоты писем не блокирует вход по существующему паролю.

Секрет SMTP вводится только в Supabase, никогда в `config.js`, SQL, GitHub или чат. Для действующего проекта подключение сохранено и доставка пробного письма подтверждена. Это не заменяет отдельную проверку регистрации нового аккаунта и перехода по ссылке подтверждения. Для массового открытого запуска потребуется также настроить CAPTCHA в Supabase и клиенте с ключами выбранного сервиса.


## Вход и восстановление пароля

В форме входа есть «Забыли пароль?». Укажите email существующего аккаунта, запросите письмо и откройте самую свежую ссылку. Событие Supabase PASSWORD_RECOVERY открывает форму нового пароля; задайте и повторите пароль (минимум 8 символов). Обновление идёт через auth.updateUser в сессии владельца, без административных ключей и изменения ролей. При несовпадении полей запрос не отправляется. Не публикуйте ссылки с токенами и пароли.

Кнопки «Показать / Скрыть» работают при входе, регистрации и в обоих полях нового пароля. Пароль не обрезается и не нормализуется. Повторная регистрация существующего аккаунта не меняет его пароль: используйте прежний пароль или восстановление. После регистрации показывается постоянное пояснение вместо исчезающего уведомления. Просроченная ссылка предлагает запросить новое письмо.

Обработчик восстановления отложен до освобождения auth-lock SDK. Признак незавершённого восстановления хранится в sessionStorage текущей вкладки (без токенов/паролей), очищается при завершении, закрытии формы и выходе. Письмо восстановления использует тот же redirect URL сайта, что и подтверждение регистрации; URL должен быть разрешён в Supabase.
